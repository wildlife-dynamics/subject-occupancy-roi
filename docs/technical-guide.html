Technical Guide

How home ranges and occupancy are calculated, the steps the workflow runs, the packages they come from, and how to recompile and test it.

Method

  1. Regions. get_features fetches the chosen EarthRanger features (by feature set, feature type or feature ID) as one GeoDataFrame in EPSG:4326, with each feature's name, feature_type and feature_set.
  2. Tracks. The subject group's observations become relocations (fixes at known-bad coordinates removed), then trajectories, dropping segments outside 0.001 m–100 km, 1 s–2 days and 0.01–500 km/h.
  3. Home ranges. calculate_elliptical_time_density_grouped builds an elliptical time-density (ETD) surface for each subject (grouped by extra__name) with an auto-scaled cell size, and returns its 50, 60, 70, 80, 90, 95 and 99.9 percentile areas. All percentiles are drawn on the map.
  4. Occupancy. Only the 99.9 percentile area is kept as the home range, and compute_region_occupancy intersects it with every region:
    • Both are reprojected to the local UTM zone of the home range (estimated from the data), so areas are in true square metres at any latitude.
    • Regions are named from name (or region, title, short_name, id, globalid, else "Region n"); rows with the same name are merged into one region; invalid shapes are repaired; regions with no area (lines, points) are skipped.
    • region_area_sqkm = the region's area; area_sqkm = area of the region inside the home range; occupancy_pct = area_sqkm / region_area_sqkm × 100, rounded to 0.1.
  5. Table. Rows with area_sqkm of 0 (regions the home range doesn't reach) are dropped, the columns are renamed for display, and the table is saved as CSV and HTML.
  6. Map. style_spatial_features styles the regions with their EarthRanger colours and icons (legend "Map Layers", grouped by feature type); the home ranges are coloured by percentile with the RdYlGn colour map (legend "Home Range").

Form overrides

spec.yaml's rjsf-overrides change the run form:

  • Subject Group Name is a drop-down of the data source's subject groups (EarthRangerEnumResolver).
  • Group by → Category offers only Subject Name (extra__name).
  • Regions has its own title and help text for each way of selecting features, and starts with an empty feature set list.

Don't add additionalProperties: false to the Regions options. Ecoscope Desktop validates the form with AJV's removeAdditional, which then deletes the list while the form works out the selected option, so Add appears to do nothing.

Recompiling

spec.yaml is the source; ecoscope-workflows-subject-occupancy-roi-workflow/ is generated from it by wt-compiler.

./dev/recompile.sh --update   # keeps the lock file and bumps VERSION.yaml
./dev/recompile.sh --install  # a new lock file, and the packages installed

Testing

Each case in test-cases.yaml runs the workflow with its settings:

pixi run --manifest-path pixi.toml -e default bash dev/pytest-cli.sh subject_occupancy_roi --all
