Troubleshooting

Common issues while configuring, running or changing subject-occupancy-roi, and how to resolve them.

Configuration & connections

A data source connection fails or times out

Check the server URL and credentials in the connection, and that you can sign in to the same server in a browser with them. The account needs API access to subjects, observations and features.

"Unknown feature set name(s)" or "Unknown feature type name(s)"

A name under Regions doesn't match EarthRanger. Names must match exactly, including capitals; the error lists the names that exist on the site. Feature types are the types listed inside each feature set in EarthRanger.

"No EarthRanger feature with id …"

A Feature IDs entry doesn't exist on this data source. Copy the ID from the feature's page in EarthRanger.

Add under Regions does nothing

The workflow was compiled with an ext-mep version older than the fix, or the Regions override in spec.yaml sets additionalProperties: false. Update ext-mep, remove that setting and recompile.

The run fails after choosing Time or Spatial grouping

This workflow only supports grouping by Subject Name. It doesn't add the time or region index that Time and Spatial grouping need, so remove those entries from Group by.

Results

The run returns no data

The subject group has no fixes in the time range. Widen the time range, or check the group in EarthRanger.

The occupancy table is empty

No subject's 99.9% home range reaches any region. Check that the regions are polygons near the tracks (lines and points are never measured), or choose different feature sets or types.

A region is missing from the table

The home range doesn't reach it, or it's a line or point feature. Regions with the same name are merged into one row.

The run is slow

Leaving Feature sets empty fetches every feature on the site, including large sets such as roads. Name only the sets or types you need.

Developing

CI says the generated files differ from the committed ones

Recompile with ./dev/recompile.sh --update and commit the changes in ecoscope-workflows-subject-occupancy-roi-workflow/.

CI says VERSION.yaml must be greater than main's

Every change needs a new version. --update bumps it: the minor number when the run form is unchanged, the major number when it changed.

A test case fails in CI but works locally

The CI reads each data source's credentials from the repository's GitHub secrets, named in .github/workflows/test.yml. Add the missing ones under Settings → Secrets and variables → Actions.
